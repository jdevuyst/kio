# Skills — fix-it mode

Trigger: running an `audit-*` skill, the `audit` umbrella skill, or `review-commits` with a fix directive.

The audit skills under `ai/skills/` (`audit-*`, `review-commits`) default to **report only** — they surface findings without touching the tree. Their `allowed-tools` frontmatter describes that report-mode surface (read/search only); a fix-directive run edits the tree under the session's normal permissions, so the frontmatter list is not a cap on fix mode. The `audit` skill is the umbrella entry point: it runs every `audit-*` skill and rolls findings into one prioritized report. When a new `audit-*` skill is added, wire it into `ai/skills/audit/SKILL.md` so the umbrella keeps running it; `audit-skills` cross-checks this.

When an audit skill is invoked with a directive to fix the findings (e.g. "run `audit-spec-drift` and fix what you find"):

1. **Account for every finding.** Apply AGENTS.md's “Account for findings” rule using the user's task and session instructions. A fix directive covers clear, bounded defects within its scope, including pre-existing ones; their age alone is not a reason to ask again. Repair each finding or explicitly record its unresolved disposition and reason. Keep deferred work in an authorized tracker or report it when tracking is not authorized. Ask before resolving uncertain intended behavior, changing a public contract, or taking on substantial unrelated work. The effective authorized contract remains the pre-work specification plus specific user supersessions: an audit, test, current implementation, same-work spec edit, or delegated directive cannot create behavioral authority. Isolate or revert unauthorized implementation from the landable range; a later decision begins newly authorized work and still requires fresh review and the applicable gates.
2. **Group fixes into large coherent publication commits.** Combine related finding-clusters, features, fixes, optimizations and refactors when they share a reviewable outcome; separate unrelated compiler/CI work when useful. Local checkpoints are allowed; use [`prepare-commits`](../skills/prepare-commits/SKILL.md) before publication when consolidation is needed, with explicit rewrite approval. Finding or task counts do not dictate commit counts.
3. **Validate proportionately before committing.** Read [`local-ci.md`](local-ci.md) and run the narrow checks that gate the changed files and behavior; documentation-only changes do not require a compiler build. Use `ci/cargo.sh` for relevant top-level Cargo checks. Preserve required exact full-matrix golden coverage and mechanical-migration evidence. The ordinary broad integration gate is `sh ci/all.sh SAMPLE_IMPL`; repository-wide `FULL_IMPL_MATRIX` requires the scope justification and user-direction checkpoint in AGENTS.md, not merely a fix directive or a commit boundary. Fix introduced regressions before committing.
4. **Don't sign off.** Commit without `git commit -s`; DCO sign-off is a separate step the user requests before a push (per AGENTS.md § Universal rules — Commits, sign-off, and push).
5. **Don't push.** Pushing is a separate, explicitly-authorized step.
6. **Report at the end.** Summarize what was fixed, the commits made, what couldn't be fixed and why, and what follow-up is worth authorizing next.
