# Kio 0.3.x

_By [Jonas De Vuyst](https://github.com/jdevuyst)_

It's been almost two months since I released Kio 0.1.0.

I got the initial release out the door just before I returned to work, after taking a 3-month sabbatical. At the time of the initial release, I did already have a large backlog of improvements that I wanted to make whenever I had tokens to burn. This backlog resulted in the 0.2.x releases. The backlog mainly included 'under the hood' changes and 'nice to have' tweaks and, for the most part, these releases were backwards compatible with Kio 0.1. Some bugs were found while implementing the backlog, however, and that did effect some backwards incompatible changes. The 0.2.x releases also include many performance improvements.

Yesterday I released Kio 0.3.0. This release contains a large number of backwards incompatible changes. For example, various keywords were renamed, the syntax of imports changed, and macros no longer have a `!`-suffix. The semantics of macros also changed significantly.

Macros could previously inspect known types and type holes alike. Combined with a constraint API for filling holes in a macro's result type, they had  _too_ much control over the type checking process. For example, it could lead to cases where `let x = <expr>; macro_call(x)` might type-check but `macro_call(<expr>)` would fail to type-check. That's just not the kind of user experience that I want for Kio. As of 0.3.0, macros can still inspect types, but macros now fail if they attempt to inspect a type hole. A macro can still see that `A & <hole>` is a product and inspect `A`. If it tries to inspect the missing type, it fails with a compile-time error. This also means that macros cannot test whether a type is known.

In future Kio 0.3.x releases I will focus on improving the quality of the various backends. I'm not happy with the interfaces that are currently emitted for various target languages. Those interfaces need to become a lot nicer to use. Once Kio gets that right, more backends can be added.
